# 02 — Frontend Core & State Management

This document details the frontend application core, lifecycle management, global reactive state architecture, and cross-window inter-process communication (IPC) bridge of **V-FEED [06]**.

---

## 1. Application Core & Lifecycle Orchestration

The core orchestrator of the entire frontend runtime is the [`App`](../../src/core/App.ts#L22) class, located in [`src/core/App.ts`](../../src/core/App.ts). It functions as a central singleton coordinating graphics, audio, vision, video queuing, calibration, and synchronization.

                                                ▼
                                  ┌───────────────────────────┐

                                  │  (Singleton Orchestrator) │
                                  └──────┬──────┬──────┬──────┘
             ┌───────────────────────────┘      │      │      └───────────────────────────┐
             ▼                                  ▼      ▼                                  ▼
 ┌──────────────────────┐            ┌──────────────────┐ ┌──────────────────┐ ┌──────────────────────┐

 │ (Three.js WebGL Pass)│            │(WebRTC 60fps Cam)│ │ (Web Audio DSP)  │ │ (BroadcastChannel)   │
 └──────────┬───────────┘            └──────────┬───────┘ └──────────────────┘ └──────────┬───────────┘

### 1.1 Startup Sequence
When [`start()`](../../src/core/App.ts#L54) executes:
1. **DOM Binding**: Attaches to required DOM elements:
   - `#stage`: The WebGL rendering canvas.
   - `#skeleton-stage`: The 2D transparent overlay canvas for phosphor skeleton drawing.
   - `#feed-video`: The hidden HTML5 `<video>` element playing YouTube / cache content.
   - `#webcam`: The hidden HTML5 `<video>` element receiving the camera stream.
   - `#boot-hint` / `#allow-camera`: The user-gesture permission overlays.
2. **Graphics Initialization**:
   - Boots [`SceneManager`](../../src/rendering/SceneManager.ts#L20).
   - Injects a procedural Gaussian noise texture generated by [`createNoiseDataUrl()`](../../src/core/textureUtils.ts#L3).
   - Generates and uploads the high-resolution alignment test pattern generated by [`createCalibrationGridDataUrl()`](../../src/core/textureUtils.ts#L33).
   - Boots [`SkeletonOverlay`](../../src/rendering/SkeletonOverlay.ts#L132).
3. **Vision & Audio Instantiation**:
   - Prepares [`CameraManager`](../../src/vision/CameraManager.ts#L5) and [`MediaPipeTracker`](../../src/vision/MediaPipeTracker.ts#L24).
   - Instantiates [`AudioEngine`](../../src/audio/AudioEngine.ts#L9) (awaiting user gesture to unlock the Web Audio Context).
4. **Video Queue Attachment**:
   - Attaches [`VideoQueue`](../../src/video/VideoQueue.ts#L63) to [`VideoTexturePass`](../../src/rendering/VideoTexturePass.ts#L4).
   - Binds the [`InteractionController`](../../src/vision/InteractionController.ts#L20) query callback so confirmed gestures automatically trigger queue lookups.
5. **Cross-Window Bridge Registration**:
   - Joins [`syncChannel`](../../src/core/SyncChannel.ts#L288) as `'MAIN_STAGE'` to listen for remote calibration commands from external windows.
6. **Main Loop Execution**:
   - Starts the `requestAnimationFrame` loop via `this.animate()`.

### 1.2 Graceful Disposal & Hot Module Replacement (HMR)
In exhibition kiosks and long-term installations, memory leaks lead to crashes. The [`App`](../../src/core/App.ts#L22) class implements a strict [`dispose()`](../../src/core/App.ts#L594) method:
- Cancels active `requestAnimationFrame` handles.
- Stops all media tracks on the camera stream.
- Closes and disposes the Three.js WebGLRenderer, geometries, textures, and custom shader materials.
- Cleans up the Web Audio Context and oscillator nodes.
- Detaches window event listeners (`resize`, `storage`, `keydown`).
- Disconnects `SyncChannel` listeners.

In [`src/main.ts`](../../src/main.ts), Vite's `import.meta.hot` hook ensures that code changes during development trigger clean disposal before the new module loads, avoiding duplicate WebGL contexts:

```typescript
// src/main.ts
const app = new App();
void app.start();

if (import.meta.hot) {
  import.meta.hot.dispose(() => {
    app.dispose();
  });
}
```

## 2. Global Reactive State Store (`StateManager.ts`)

Global state is managed using **vanilla Zustand** via [`useAppStore`](../../src/core/StateManager.ts#L487) in [`src/core/StateManager.ts`](../../src/core/StateManager.ts). Zustand was chosen over Redux or React Context because it works outside of a UI framework hierarchy, allowing high-frequency direct reads and writes inside the 60 FPS animation loop without garbage-collection overhead.

### State Slice Architecture

```
                                  ┌──────────────────────────────┐
                                  │    useAppStore (Zustand)     │
                                  └──────────────┬───────────────┘
         ┌──────────────┬──────────────┬─────────┴────┬──────────────┬──────────────┬──────────────┐
         ▼              ▼              ▼              ▼              ▼              ▼              ▼
   ┌───────────┐  ┌───────────┐  ┌───────────┐  ┌───────────┐  ┌───────────┐  ┌───────────┐  ┌───────────┐
   │  shaders  │  │ tracking  │  │interaction│  │   video   │  │   audio   │  │   quota   │  │  frames   │
   │  (GLSL)   │  │ (Vision)  │  │(Semantics)│  │ (Playback)│  │   (DSP)   │  │ (YouTube) │  │ (Overlay) │
   └───────────┘  └───────────┘  └───────────┘  └───────────┘  └───────────┘  └───────────┘  └───────────┘
```

### Detailed State Slices

#### 1. `ShaderUniformsState`
Controls the single-pass composite shader uniforms:
- `matrixSplit`: `boolean` — Toggles between 2×3 matrix mode (6 CRT screens) and single flat-screen mode.
- `bezelWidthX`, `bezelWidthY`: `number` — Interior horizontal and vertical gap spacing between virtual CRT frames.
- `bezelOuter`: `number` — Exterior margin padding around the 6-screen totem.
- `bezelComp`: `number` — Geometric bezel compensation (interpolates between seamless video pass-through and physical bezel masking).
- `cornerRounding`: `number` — Curvature radius of the CRT glass tube corners.
- `bezelChassis`: `boolean` — Toggles realistic textured dark bezel chassis rendering between monitor frames.
- `perScreenVariance`: `number` — Phase drift factor between individual monitors.
- `globalFlipH`, `globalFlipV`, `globalRotation`, `globalFineRotation`: Global orientation controls.
- `screenFlips`, `screenOffsets`: Per-screen orientation and translation offsets.
- `cornerOffsets`: `ScreenCornerOffsets[]` — 24-point (4 corners × 6 screens) keystone quad offsets.
- `showCornerHandles`: `boolean` — Toggles draggable corner handle rendering.
- `curvature`, `tubeCurve`: `number`, `boolean` — Spherical barrel distortion parameters.
- `scanlineIntensity`, `phosphorMask`, `vignette`: CRT physical phosphorescence attributes.
- `rgbSplit`, `vHold`, `hJitter`, `noiseGain`, `signalLock`: Analog transmission flaw coefficients.
- `screenNoiseGains`, `screenSignalLocks`: Array of 6 floats per monitor for localized antenna tuning.
- `rippleStrength`, `rippleCenter`: Normalized hand-targeted electromagnetic distortion wave parameters.

#### 2. `TrackingState`
Maintains optical telemetry from MediaPipe:
- `present`: `boolean` — True if a spectator is detected in the frame.
- `distance`: `number` — Calibrated distance in meters (default range 1.0m to 3.0m).
- `velocity`: `number` — Inter-frame joint displacement speed.
- `torsoArea`: `number` — Normalized bounding box area of visitor's chest/torso.
- `leftHand`, `rightHand`: `HandPoint` — Normalized `(x, y, z)` coordinates and active state of spectator hands.
- `confidenceThreshold`: `number` — Minimum detection score (0.0 to 1.0).
- `mirrorCamera`: `boolean` — Flips horizontal camera tracking coordinates.
- `cameraRotation`: `number` — `0 | 90 | 180 | 270` degrees rotation for portrait-mounted cameras.
- `screenPresences`: `number[]` — Array of 6 floats indicating visitor presence per CRT quadrant.
- `personCount`: `number` — Total number of detected persons in the optical FOV.
- `maxNumPoses`: `number` — Maximum tracked bodies for MediaPipe.
- `antennaLocalWeight`, `antennaHandBoost`, `antennaSmoothing`, `antennaFalloffRadius`: Tuning parameters for the human antenna engine.

#### 3. `InteractionState`
Maintains high-level spectator semantics:
- `enabled`: `boolean` — Master toggle for algorithmic interaction.
- `activePose`: `SemanticPose` — `'POSE_ANTENNA' | 'POSE_DIAL_TUNER' | 'POSE_SURPRISE' | 'POSE_WINGSUIT' | 'POSE_LOOP_HALO' | 'POSE_SIGNAL_LOCK' | 'NONE'`.
- `densityState`: `AudienceDensity` — `'SOLO' | 'DUO' | 'GROUP' | 'EMPTY'`.
- `kineticState`: `KineticState` — `'HIGH_MOTION' | 'RHYTHMIC' | 'STILLNESS' | 'STEADY'`.
- `chromaState`: `ClothingChroma` — `'WARM_RED' | 'DARK_NEUTRAL' | 'COOL_BLUE' | 'NEUTRAL'`.
- `kineticEnergy`: `number` — Normalized 0.0 to 1.0 energy metric.
- `holdProgress`: `number` — 0.0 to 1.0 countdown progress towards the 1.8-second gesture trigger.
- `cooldownRemainingSec`: `number` — Remaining lock seconds before a new query can trigger.
- `lastQuery`: `string | null` — Text of the last synthesized YouTube query.

#### 4. `VideoState` & `AudioState`
- `videoMode`: `VideoMode` — `'live'` (online YouTube queue), `'cache'` (local MP4 files), or `'grid'` (alignment test pattern).
- `currentVideoUrl`: `string | null` — Active playing video source URL.
- `audioUnlocked`: `boolean` — Web Audio Context run state.
- `audio`: `AudioState`:
  - `masterVolume`: `number` — Master audio volume (0.0 to 1.0).
  - `videoVolume`: `number` — Ingested video soundtrack volume (0.0 to 1.0).
  - `noiseVolume`: `number` — Procedural RF static noise volume (0.0 to 1.0).
  - `humVolume`: `number` — 15.734 kHz CRT flyback hum volume.
  - `antennaModulation`: `boolean` — Toggles proximity/antenna-driven audio filtering.
  - `muted`: `boolean` — Master mute toggle.

#### 5. `QuotaState`
- `unitsUsed`: `number` — YouTube Data API v3 units consumed today.
- `dailyBudget`: `number` — Daily hard quota limit (default 9,000 units).
- `percentage`: `number` — Used percentage of the daily budget.
- `isProtectedMode`: `boolean` — True when quota limit is exceeded, forcing cache playback.

#### 6. `FrameState`
Controls decorative CRT chassis and sci-fi frame overlays:
- `showScreenFrames`: `boolean` — Toggles screen frame overlay rendering.
- `style`: `FrameShapeStyle` — `'crt-tube' | 'bracket-corners' | 'rounded-rect' | 'industrial-bezel' | 'minimal-ticks'`.
- `opacity`: `number` — Global frame overlay opacity (0.0 to 1.0).
- `transforms`: `ScreenFrameTransform[]` — Array of 6 per-screen position offsets and fine rotations.

## 3. Mathematical Utilities & Constants

Layout geometry and physical constants are partitioned between [`src/core/constants.ts`](../../src/core/constants.ts) and [`src/rendering/MatrixSplitter.ts`](../../src/rendering/MatrixSplitter.ts):

| Constant | Location | Value | Purpose |
| :--- | :--- | :--- | :--- |
| `CRT_FLYBACK_HZ` | `src/core/constants.ts` | `15734` | Frequency of NTSC horizontal scanline deflection coil whine |
| `IDLE_TIMEOUT_MS` | `src/core/constants.ts` | `5000` | Inactivity duration before screens drop into RF static snow |
| `DEFAULT_VIDEO_ASPECT`| `src/core/constants.ts` | `9 / 16` (~0.5625) | Default vertical video aspect ratio |
| `MAX_DEVICE_PIXEL_RATIO`| `src/core/constants.ts` | `2.0` ([`L6`](../../src/core/constants.ts#L6)) | Caps WebGL DPR on Retina displays to protect GPU frame budget |
| `MATRIX_COLUMNS` | `src/rendering/MatrixSplitter.ts` | `2` | Number of columns in CRT totem |
| `MATRIX_ROWS` | `src/rendering/MatrixSplitter.ts` | `3` | Number of rows in CRT totem |
| `TOTAL_SCREENS` | `src/rendering/MatrixSplitter.ts` | `6` | Total count of CRT monitors |

Canvas dimensions are resolved dynamically at runtime via `getViewportSize()` and `getViewportAspect()` in [`src/core/constants.ts`](../../src/core/constants.ts) to adapt seamlessly to 1080×1920 kiosk displays or arbitrary window sizes during development.

### Procedural Texture Generation (`textureUtils.ts`)
Located in [`src/core/textureUtils.ts`](../../src/core/textureUtils.ts):
- [`createNoiseDataUrl(size: number)`](../../src/core/textureUtils.ts#L3): Generates a tileable 256×256 base64 PNG containing high-frequency Gaussian radio noise. Uploaded to GPU texture unit `tNoise` for analog RF static simulation.
- [`createCalibrationGridDataUrl(w: number, h: number)`](../../src/core/textureUtils.ts#L33): Dynamically renders a 1080×1920 SVG/Canvas test pattern featuring:
  - 2×3 quadrant dividers with numbered labels (`CRT [01]` through `CRT [06]`).
  - SMPTE standard color bars.
  - Optical focus crosshairs and concentric geometry circles.
  - 10-pixel alignment grid for hardware bezel adjustment.

## 4. Cross-Window Synchronization Bridge (`SyncChannel.ts`)

The [`SyncChannel`](../../src/core/SyncChannel.ts#L116) class enables zero-latency bidirectional communication between the Main Stage and the standalone Operator Calibration Console.

### Transport Layer
1. **Primary Transport**: The browser's native `BroadcastChannel` API (`channel name: 'vfeed-sync'`). This provides sub-millisecond inter-tab/inter-window communication without network traffic or WebSocket server requirements.
2. **Fallback Transport**: If `BroadcastChannel` is unsupported or restricted, the bridge automatically falls back to `window.addEventListener('storage', ...)`.

### Heartbeat & Connection State
Both windows transmit a 2-second heartbeat (`PING` / `PONG`). If no heartbeat is received within 4 seconds, [`isPeerConnected()`](../../src/core/SyncChannel.ts#L263) returns `false`, causing the Calibration Console to display a visual `○ WAITING FOR MAIN STAGE...` warning badge.

### State Synchronization Flow

```
   OPERATOR CONSOLE (Window 2)                           MAIN STAGE (Window 1)
   ───────────────────────────                           ─────────────────────
   User drags keystone handle
               │
               ▼
   syncChannel.sendStatePatch({
     shaders: { cornerOffsets }
   })
               │
               ├─────── BroadcastChannel: 'STATE_PATCH' ───────►
                                                                   │
                                                                   ▼
                                                       useAppStore.getState().patchShaders(...)
                                                                   │
                                                                   ▼
                                                       GLSL uniforms updated in next frame (0ms)
                                                                   │
                                                                   ▼
                                                       Main Stage visual warp shifts instantly
```
